# 01. Mom Test 인터뷰 리포트

**페르소나:** 길이 단위 변환을 반복적으로 다루는 개발자  
**일자:** 2026-06-05  
**프로젝트:** UnitConverter_27

---

## 1. 표면 문제 (잘못된 정의)

“길이 단위 변환 **프로그램/앱을 만든다**” — meter를 feet 등으로 **바꿔 주는 도구**가 필요하다.

---

## 2. 진짜 문제 (한 문장)

meter로 된 거리를 feet로 쓸 때마다 **환산 상수를 다시 찾고**, **어느 숫자가 맞는지 스스로 판단한 뒤** 계산기로 곱해 문서에 넣는 데 **회당 약 1분**이 들고, 한 달에 그렇게 **약 20번** 반복된다.

---

## 3. Mom Test 증거 (인터뷰이 발화 인용)

- “지난번에 meter를 feet로 바꿀 때 **비율을 매번 구글링**했다.”
- “**1미터가 몇 feet인지 정확한 숫자가 헷갈렸다**. 솔직하게 말하면 어려워서 **굳이 외우지 않았다**.”
- “지난 **한 달** 안에 … **20번** 정도가 되는 것 같다.” / “검색에 걸리는 시간을 포함해서 **1분** 정도 걸렸던 것 같다.”

---

## 4. 관찰된 행동 패턴

| 항목 | 내용 |
|------|------|
| 워크플로 | 구글(비율 확인) → 계산기(거리 × 비율) → 문서(회의록) |
| 비율 선택 | 구글 스니펫 **3.28084** 사용; **3.281**(근사)도 보였으나 “조금 더 정확히”로 **3.28084** 선택 |
| 산출물 | 회의록에 기록, **다른 사람도 열람** |
| 외부 피드백 | feet 값·단위 관련 **질문·수정 요청 없음** |

---

## 5. 검증 상태

| 신호 | 강도 | 비고 |
|------|------|------|
| 빈도·재현 (월 ~20회, 회당 ~1분) | 강함 | 과거 행동으로 확인 |
| 상수 신뢰·판정 부담 | 강함 | 헷갈림, 외우지 않음, 3.28084 vs 3.281 선택 |
| 회의록·동료 압력 | 약함 | 피드백 0 — 필수 pain으로 단정 불가 |
| 포기·미룸·시간 낭비 | 미검증 | 인터뷰 종료 시 미응답 |

---

## 6. README와의 gap (참고)

README 예시 출력은 `2.5 meter = 8.2 feet` 등 **반올림·근사** 표기. 인터뷰에서는 **3.28084** 수준의 정확도를 선호. 회의록에 **8.2 feet**만으로 충분했는지는 추가 인터뷰 필요.

---

## 7. 다음 검증 가설

1. 20회 중 구글+계산기를 **포기**하고 meter 그대로/대충 넘긴 적이 있는지  
2. meter↔feet 외 **동일 패턴** 단위 쌍과 빈도  
3. 비율을 메모·스니펫에 저장해 보고 **중단한 이유** (과거 1회)
