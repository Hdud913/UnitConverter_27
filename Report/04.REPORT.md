Mom Test·워크북에서 도출한 **진짜 문제**(상수 재탐색·판단·수동 계산·귀찮음으로 인한 포기)를 해소하기 위해, `spec` 브랜치에서 **기술 명세 3종**과 **Cursor 기술 체계 4종**(Rule · Command ×2 · Skill)을 구축했다. 구현(`unit_converter/` 패키지)은 **미착수** — TDD RED 단계부터 `TRACEABILITY.md` ID 순으로 진행 예정.

| Mom Test 성공 기준 | Spec·TDD 대응 |
|--------------------|---------------|
| ① 비율 구글링 제거 | 비율 단일 출처 (`tdd-rules.mdc`), FR-02 TC |

## 4. Dual-Track TDD 설계

| Track | Layer | 테스트 | 범위 |
|-------|-------|--------|------|
| **A** | boundary (UI) | `tests/test_cli.py` | 입력 검증, CLI 오류, `--format` |
| **B** | entity (Logic) | `tests/test_converter.py` | 변환 비율, Registry, OCP |

**공통 규칙**

- RED: `pytest.fail("RED: [ID] — 구현 없음")` 만 · 구현 금지
- GREEN: 최소 구현 · 1 RED 묶음 = 1 커밋
- REFACTOR: Golden Master → 스멜 탐지 → Safe Refactor → 전체 PASS
- 금지: Domain Mock on Logic Track, skip/xfail, assert 완화
